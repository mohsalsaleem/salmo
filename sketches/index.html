Pick a reactivity model

Two ~100-line sketches of the same demo: a filterable list and a counter, built with tagged-template syntax. Read the code, click around, then tell me which feels right and we'll grow it into the real framework.

Signals

Like Solid / Vue 3. State is a signal(). Effects auto-subscribe to the signals they read. No virtual DOM — the framework binds reactive holes directly to DOM nodes.

  • Smaller core (~50 lines)
  • Updates are surgically scoped — no diff pass
  • Closer to how the browser actually works
  • You have to call signals as functions: count() not count
  • Memory cleanup of stale subscriptions is its own problem

VDOM + hooks

Like a tiny React. Components are functions that return a vnode tree. State via useState. A diff figures out the minimal DOM patches.

  • Familiar mental model — component re-runs on state change
  • State is just a value: count not count()
  • Diffing is interesting to write
  • ~2x more code (~110 lines)
  • Every keystroke re-runs the entire component body
  • Hooks rely on call-order — same gotchas as React

What to look for in each demo

  • A counter at the top tracks how many times the setup / component runs.
  • In the signals demo it stays at 1 forever. In the VDOM demo it climbs on every keystroke.
  • Open DevTools → Elements and watch which nodes flash (highlight on update) — signals only flashes the changed text node; VDOM flashes anything the diff touches.
